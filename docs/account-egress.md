# 账号出口代理与 sub2api 接入

## 出口规则

- 账号页的“出口代理”管理 SOCKS5 节点；支持 `socks5://`（本地 DNS）和 `socks5h://`（代理 DNS），以及用户名密码认证。
- 账号可单独绑定，也可选择多个 OpenAI 账号批量绑定。未绑定的账号直连；不自动轮换节点。
- 已绑定节点不可用、停用、认证失败或配置读取失败时，请求失败，不自动改为直连。
- 绑定适用于账号的 HTTP/SSE、WebSocket、Token 刷新、已有账号重新授权、额度、资料和模型目录请求。首次新增账号的导入或授权发生在绑定建立之前，仍使用默认直连路径。
- 出口在每次账号请求准备时读取。已开始的请求不会被强制中断；节点或绑定版本变化后，新请求不会复用旧出口的 WS 连接。本地连接续接不能跨出口迁移，客户端可能需要重新开始会话。
- 公共发布画像和应用更新查询不是账号请求，不使用账号绑定。

## 配置与安全

1. 新增节点，填写名称与完整 URI。凭据中的特殊字符应使用百分号编码。
2. 在账号出口列或“更多操作”中选择节点，或批量选择账号后点击“绑定出口”。
3. 通过既有“测试连接”验证账号请求；生产出口 IP 和真实上游可用性需要实际节点与账号验证。
4. 显式选择“直连”解除绑定。仍有绑定账号的节点不能删除。

管理接口为 `GET /api/admin/egress`、`POST /api/admin/egress/update`，使用现有管理会话认证。节点更新和删除使用 `expectedRevision` 防止覆盖并发变更。批量绑定为单个数据库事务。

代理 URI 保存在 PostgreSQL，沿用本项目现有凭据存储边界，没有新增静态加密机制。数据库与备份应限制访问。列表、日志错误和审计事件不回显认证信息；编辑时凭据留空表示保留现有配置。

新增数据库迁移为 `0002_account_egress.sql`，不改动初始迁移。升级前备份数据库与部署配置；回退镜像时保留新增表，不执行破坏性 down migration。

## sub2api

- 在 sub2api 中建立 OpenAI API Key 类型上游，凭据填写本服务创建的客户端 API Key，而非 OpenAI 账号 Token。
- Base URL 指向 sub2api 容器可达的本服务地址，使用 `/v1` API 前缀；Docker 内的 `127.0.0.1` 指向当前容器，不能直接当作宿主机地址。
- 使用 Responses 原生请求，启用 `openai_passthrough`；WebSocket 模式需要单独配置。具体 URL 拼接应核对已部署 sub2api 版本，避免重复 `/v1`。
- 自动透传仍可能执行兼容修正、头部白名单和策略校验，不等于逐字节透传。
- 原生流式上下文压缩通过 `/responses` 请求中的 `compaction_trigger` 传递。缺少旧 `/responses/compact` 独立接口，不代表这种新路径不可用。
- 本次对 sub2api 的结论来自源码核查。未修改其生产账号配置，也未宣称完成真实 sub2api -> 本服务 -> OpenAI 的压缩和 WS 端到端验收。

## 验证

- OpenAI provider：555 项测试通过，包含 SOCKS 认证、远端 DNS、出口隔离、HTTP/WS 故障不直连、Token 刷新、跨出口续接限制。
- gateway-core：277 项；gateway-admin：99 项；gateway-api 管理接口：106 项，架构检查：5 项。
- 真实本地 PostgreSQL：127 项测试通过，包含新增迁移、节点 CAS、批量回滚、删除保护和审计脱敏。
- Clippy 严格检查、前端 ESLint、类型检查和生产构建通过。
- 浏览器模拟 API 检查覆盖 1440x1000 与 390x844，验证节点增删改、凭据不回显、单账号绑定、批量恢复直连和加载失败重试。
- gateway-api 全量测试运行曾超时；上述管理接口和架构子集已单独完成，不将超时运行计为通过。

浏览器检查依赖 Python Playwright 和已安装浏览器，例如：

```sh
python frontend/tests/egress_ui.py --channel msedge --url http://127.0.0.1:5187
```

浏览器测试使用模拟接口，不消耗上游额度，也不替代实际代理出口的生产验证。
